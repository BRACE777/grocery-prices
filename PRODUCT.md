# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Static HTML and CSS, no framework and no build step, generated by a Python
script. Confirmed by the user when offered a framework alternative.

## Users

One person, shopping for a household in Melbourne. Single audience, no sharing,
standard text size. Both confirmed.

They open the page on a phone, at home, on Wednesday morning. Australian
supermarket specials reset on Wednesday, so that is the only moment the page
needs to be right. The job is deciding which of the two chains to shop at this
week, and which pack size of a given product to buy.

They are not reading it in the aisle. Live-in-store lookup was considered and
explicitly ruled out, because it forces a cloud-hosted fetch that the retailers
block.

## Product Purpose

Compare the current price of 23 pinned grocery products across Woolworths and
Coles, and show which items are on special this week.

Success is a single glance that answers two questions: what went on sale, and
which chain is cheaper for the things I buy. The user's stated buying rule is
lowest price per 100g, so the normalised unit price is the number that decides,
not the shelf price.

## Positioning

It tracks one specific shopping list rather than a whole catalogue. Every row is
a product the user actually buys, pinned by product identifier, so nothing
drifts onto a near-miss match. A general price-comparison site cannot do this
because it does not know which 23 things matter.

## Operating Context

- A Python script runs on the user's own Windows PC, every Wednesday at 7am,
  and on next wake if the machine was asleep. Manual runs are also possible.
- Output is a single static page pushed to GitHub Pages, so the phone can open
  it from anywhere without the PC being on.
- Fetching cannot run in the cloud. Woolworths returns 403 to data centre
  addresses, verified against a residential connection returning 200.
- Requests go out through curl. Imperva, which fronts Coles, serves the real
  site to curl and a bot challenge to Python's own HTTP client from the same
  address with identical headers. Verified by direct comparison.
- Coles challenges any request sent with `Accept-Language: en-AU` and serves
  the real site to `en-US`. Measured by bisecting the header set one header at
  a time, with a control. Woolworths is unaffected.
- A challenged cookie jar stays challenged, so a failed read is retried with a
  new jar rather than the old one.

## Capabilities and Constraints

- 23 rows in 7 categories: savoury snacks, drinks, pantry and sauces, mince,
  chicken, noodles, frozen and dessert.
- 15 rows are stocked by both chains. 3 are Woolworths only, 5 are Coles only.
  Single-chain rows show one price, which the user confirmed is correct
  behaviour rather than an error.
- Unit price is normalised per row onto one of six bases: per 100g, per 100mL,
  per kg, per can, per pack, per piece. The two chains describe the same pack
  differently, so quantities are merged from the retailer's size string and the
  row title.
- Sale status comes from each retailer's own was-price and promotion flag.
- No member pricing. Neither Everyday Rewards nor Flybuys prices are exposed
  without signing in, confirmed across 250 Woolworths and 53 Coles products.
- No price history. Available in the feeds and deliberately discarded by the
  user, so the page cannot distinguish a token discount from a genuine low.
- No store selection. Woolworths offers none without signing in, and two
  Victorian Coles stores returned identical prices. Prices are national online
  prices. In-store may differ.
- A failed fetch must render as an empty cell highlighted red, meaning the
  pinned identifier needs fixing. Not stocked must look different from failed.
- Products are added by pasting a retailer product web address into a helper
  script. The list is expected to grow.

## Brand Commitments

No logos of either retailer. Chain identity is carried by colour alone:
Woolworths green and Coles red, which the user chose so a price never needs a
header to be read.

## Evidence on Hand

- `site/data.json`, a real fetch of all 38 offers across both chains, zero
  failures. This is live data, not fixtures.
- `products.json`, the 23 pinned products with verified retailer identifiers.
- Current data includes 13 items on special, 12 rows with a clear cheaper
  chain, and 3 genuine ties, so the design must handle all three states.

## Product Principles

1. The unit price decides. Shelf price is context, price per 100g is the answer.
2. Never guess a product. A pinned identifier or an honest gap, nothing in
   between.
3. Distinguish missing from broken. Red means the user has work to do; grey
   means the chain does not sell it.
4. Say how old the numbers are. A weekly page that hides its own staleness is
   worse than no page.
5. One glance, one screen, one hand. The whole week's decision on a phone.
